# superwork · 扁平执行/审查工作流

使用 `superwork` 的每个普通 DSH 会话默认都是自己组织的根线程。根线程只创建一层直属工作代理：执行代理负责产出，审查代理只读审查；不再设置项目经理层，也不允许工作代理继续嵌套开线程。

## 硬规则

- 正式协作单位是普通独立 Session，不写 `origin: 'subagent'`。
- 组织固定为根 `depth 0` → 工作代理 `depth 1`；工作代理禁止再开下级。
- 工作代理角色只有 `work` 与 `review`，都只属于一个根线程。
- 执行与审查不能横向通信；消息和返工由根线程及状态机中转。
- 审查代理权限强制 `read-only`，不能通过模板或调用参数放宽。
- 执行交付必须先 `submit_completion`；`start_review` 自动固定合同版本、交付 ID、交付 digest 与证据。文件/日志证据由服务端计算 SHA256，最终验收前再次校验实际文件。
- 每一版执行交付都必须独立审查 PASS，根线程才能 `accept_completion`。旧 PASS 不能验收新版交付。
- 任一 FAIL 在全部审查席提交后自动把正式问题清单退回执行代理，并进入新一轮执行；修复后必须完整重审。根线程可用 `cancel_review` 更换失联审查席，但已有 FAIL 仍会打回并计入返工，不能洗掉。
- 合同修订会立即作废旧待验收交付；执行、审查、验收等身份敏感动作只开放绑定当前代理身份的模型工具，不开放可伪造身份的本地 HTTP 写接口。
- 工作代理可以调用 `rename_self` 改自己的显示名；角色、权限和状态不随名称变化。
- 状态只由 superwork 推进：派工/合同→running，交付/审查→waiting，升级→blocked，最终验收→complete。`report_to_parent` 不能改状态。
- 权限只能同级或缩小；限定工作区按真实 `realpath` 校验，符号链接不能逃逸。
- 每个根线程拥有独立组织树；右侧 superwork 边栏只显示当前根的直属执行/审查代理。

## 设置页

设置→工作流只保留“工作代理线程”模板。每张模板可配置：

- 名称与启用状态
- 执行或审查类型
- Agent 预设、提供方、模型、思考程度
- 权限（审查固定只读）
- goal 开关、最大轮次、附加指令

旧 v2 三列设置会自动迁移，只保留原二级执行/审查卡；旧主线程卡和项目经理卡退休。

## 右侧边栏

better-sidebar 的 `superwork` 页按当前会话解析所属根，只列直属工作代理，显示代理自定义名称、执行/审查角色和系统状态。工作代理从左栏归档隐藏，点右栏条目会临时解档打开，切走后重新归档。

## 测试

```bash
cd /Users/yu/.dsh/profiles/desktop/superwork
npm test
```

标准测试命令运行全部 `*.test.js`，覆盖配置迁移、权限、创建/恢复、合同、固定交付、独立审查、自动返工、自助更名、系统状态、右栏树和持久信箱。
